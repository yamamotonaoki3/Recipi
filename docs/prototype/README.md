# Recipi プロトタイプ（要件検討用の叩き台）

`index.html` は、[要件定義書](../requirements/README.md)を踏まえて作った **クリック可能なモックアップ**です。実バックエンドはなく、すべてブラウザ内のモックデータで動きます。要件をさらに煮詰めるための叩き台としてお使いください。

- **Artifact（ブラウザですぐ触れる版）**: [claude.ai/code/artifact/5968477c…](https://claude.ai/code/artifact/5968477c-3b8b-421d-8b8d-fef2522fbaba)
- **ローカルで開く**: `docs/prototype/index.html` をブラウザで開くだけ（ビルド不要）

## 触り方

1. 起動 → スプラッシュ → ログイン画面。メールとパスワードを適当に入れて「ログイン」（空欄だとエラー表示の確認）。
2. 下部の **ボトムナビ**（ホーム / ＋ / 通知 / マイページ）で主要画面を移動。検索はホーム画面最上部の常時固定検索窓で行う。
3. 右上（狭い画面では「☰ 画面インデックス」）から全画面へジャンプできます。
4. **「📝 設計メモ」** を ON にすると、各画面に *未確定事項・割り切り* の注記と、一覧画面の **状態切替**（通常 / 空 / エラー）が出ます。要件レビュー時はこれを見ながら。
5. **「◐ テーマ」** でライト / ダーク / 自動を切替。
6. **「↺ リセット」** でモックデータとログイン状態を初期化。

## 再現している画面（全 13）

認証: スプラッシュ / ログイン / サインアップ / パスワードリセット（2 ステップ）
メイン: ホーム（常時固定の検索窓 ＋ 4 サブタブ）/ 通知一覧 / レシピ作成・編集 / マイページ
サブ: レシピ詳細 / 自分のレシピ一覧 / フォロー・フォロワー（2 タブ）/ プロフィール編集 / ユーザープロフィール（他人）

## 再現している操作

- ボトムナビ遷移・戻る・画面遷移図（[transitions.md](../requirements/screens/transitions.md)）のフロー
- ホームの 4 サブタブ切替、空状態
- ホーム上部の常時固定検索窓（空白区切り AND の簡易版。表示中のサブタブの中で絞り込み、× / 空でクリア）
- レシピ詳細: ♡ トグル（楽観・数 ±1）、フォロートグル、材料グループ表示（フラット / 見出し）、参照材料リンク（生存 → 遷移 / 削除済み → 「このレシピは削除されました」）、手順、感想の投稿・編集・削除、本人の編集 / 削除 + 確認ダイアログ
- レシピ作成・編集: サムネ選択、人数ステッパー、材料グループの追加 / 削除、材料行の追加 / 削除、「レシピから選ぶ」ピッカー（自分のレシピのみ）→ リンク設定 / 解除、手順行の追加 / 削除、「画像を追加」、公開トグル、保存 → 詳細、未保存で閉じると破棄確認
- 通知: 未読強調、行タップで対象へ + 既読、「すべて既読」でバッジ 0
- サインアップ / パスワードリセット: パスワード確認欄の不一致をクライアント側でブロック
- プロフィール編集: 公開トグル、アバター変更、保存、アカウント削除 → 確認 → ログイン
- フォロー・フォロワー 2 タブ、ユーザー行のフォロートグル
- ライト / ダークテーマ

## モックの割り切り（実物と違う点）

| 項目 | プロトタイプでの扱い |
| --- | --- |
| 画像 | 色ブロック + 絵文字で代用（サムネ・手順画像・アバター・感想画像） |
| 通信・ローディング | 即時。エラー / 空は「設計メモ」ON の状態切替で確認 |
| 無限スクロール・カーソルページング | 省略（1 ページ表示） |
| 検索の正規化・かなカナゆれ吸収 | 簡易（小文字化 + 部分一致 + 空白 AND のみ） |
| 認証（トークン / リフレッシュ / token_version） | 省略。入力すればログイン成功 |
| 材料・手順の並べ替え（ドラッグ / 上下ボタン） | 未実装（追加 / 削除のみ） |
| デスクトップのナビゲーションレール（広幅レイアウト） | 端末カラム表示のみ。レール切替は未実装 |
| バリデーションの網羅 | パスワード一致・タイトル / 材料 / 手順の必須のみ。文字数上限などは注記どまり |
| データ永続 | ブラウザの localStorage に保存（他端末・他ブラウザには共有されない） |

## 要件を煮詰めるときの使い方

- 「設計メモ」の注記が指す `todo.md` の項目（材料グループの上限、並べ替え UI、検索の正規化仕様、通知バッジ更新方式 など）を、画面を触りながら判断する。
- 画面の並び順・情報量・遷移に違和感があれば、対応する `docs/requirements/screens/*.md` を直す（画面設計と機能仕様が食い違ったら機能仕様を正とする）。
- このプロトタイプ自体は使い捨て。要件が固まったら本実装（TypeScript / Expo）は要件定義書から作り直す。
