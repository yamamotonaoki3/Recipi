# npm依存のセキュリティ更新（Issue #350）

## 適用した修正

- Node.js本体とは別にインストールされるUndiciを、6系は6.29.1以上、7系は7.30.1以上にする。
- sharpは0.35.5以上へ更新する。
- Axios、proxy-addr、shell-quote、js-yaml 4系は同じメジャーの修正版を`overrides`で選択する。
- ロックファイルの互換範囲内更新と、Appium/WebdriverIO系の同一メジャー更新を行う。
- `npm audit fix --force`は使用しない。ExpoやReact Nativeの旧版へのダウングレードも行わない。

## 残っている問題

この変更だけで監査がゼロになるとは主張しない。2026-10-23の監査では、Appiumのバンドル依存を含む70件（Critical 7 / High 57 / Moderate 6）が残った。親パッケージへの波及も数えるため、独立した脆弱性の件数ではない。

- `appium-uiautomator2-driver`に同梱されたAxios 1.19.0、proxy-addr 2.0.7、sharp 0.35.4、shell-quote 1.10.0が残る。通常の`overrides`では同梱物を置換できなかった。Appium本体・ドライバーの更新または同梱方式の変更を別途判断する必要がある。
- `node-forge` 1.4.0の署名検証問題（[GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv)）は告知に修正版がない。
- `serialize-javascript` 6系は7.0.5以上への変更が必要。Mocha/WebdriverIO側の依存更新とAndroid E2Eによる互換性確認が必要。
- `braces` / `micromatch`、`decode-uri-component`、`postcss-selector-parser`、`basic-ftp` / `extract-zip`などが残る。監査はExpo/Jest・Tailwind・WebdriverIOのメジャー変更も提案しており、本Issueの互換更新とは分けて判断する。

npmで通常依存として分類されるExpo/Metro関連にもビルドツールが含まれる。npmの分類だけで、配布アプリや本番APIから脆弱な処理へ到達できるとは断定しない。一方で、開発環境・CIの依存にもなるため監査結果は無効化しない。

## 検証

品質チェック、既存の単体テストとWebビルドを実行する。Web E2Eでは画像アップロード・表示を含む既存シナリオを利用する。Appium/WebdriverIOの同一メジャー更新についてAndroid実行の確認が必要な点は、Web E2Eの成功とは分けて扱う。

初回Android E2Eは9ファイル中8件成功し、アバターの写真選択だけ失敗した。保存した画面構造ではAOSP版の`com.android.providers.media.module:id/icon_thumbnail`が存在していたが、テストはGoogle版の識別子へ固定されていた。両方のパッケージに限定して一致するロケーターへ修正し、同じ写真選択・切り抜き・確定シナリオを再実行する。

## 2026-10-24 再監査・残件の分割（Issue #350）

- Node.js 24.22.1 / npm 11.19.1で再監査した結果、`npm audit`は40件（Critical 7 / High 25 / Moderate 8）、`npm audit --omit=dev`は10件（High 4 / Moderate 6）。npmの依存分類は、配布アプリや本番コードからの到達可能性を示すものではない。
- 現在のツリーに`npm-shrinkwrap.json`は存在しない。Issue #350に記録されていたshrinkwrapの説明は現状と一致しないため、依存固定の根拠として扱わない。
- Appium 3.8.0 / UiAutomator2 Driver 8.7.0を確認した。公開済みの8系は8.7.0までで、Driverに同梱された脆弱な依存は通常のnpm overridesでは置き換えられない。`npm audit fix`が8.6.1へ下げる場合があるが、既知の検証で残件を解消しなかったため8.7.0を維持する。
- `node-forge`の公開最新版は1.4.0で、GHSA-86w9-cpqp-85rvの修正版は確認できない。auditの強制修正案にはExpo 44への破壊的ダウングレードが含まれるため適用しない。
- 残件はAndroid E2E依存（#353）、Expo SDK / Router依存（#354）、Tailwind / PostCSS依存（#355）へ分割した。WebdriverIO / Mocha、Expo Router、Tailwindの修正案はメジャー移行を伴うため、各Issueで互換性と受け入れテストを確認する。
- `npm update`後に`npm ci`が失敗し、Appium同梱Sharp 0.35.4のmacOS / Linux向けoptional依存がlockfileから欠けていることを確認した。既存lockfileと`node_modules`を引き継がず、manifestだけを置いた空ディレクトリからlockfileを再生成すると全OS分が入り、プロジェクトで`npm ci`が成功した。
- 最終lockfileでlint、format、typecheck、Jest 99スイート / 1,582テスト、Webビルドは成功した。ローカルAndroid E2Eは接続端末がなく、Recipi用Dockerサービスも起動していないため未実行。Android E2Eの成功とは記録しない。
