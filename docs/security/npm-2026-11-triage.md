# npm audit 残件の仕分け（2026-11-11、Issue #359）

`expoApp/` の `npm audit` 残件 57 件を、アプリに同梱されて端末上で実行されうるもの（runtime）と、開発・ビルド・テスト専用のもの（dev / build）に仕分け、後続作業へ割り当てた。**依存・lockfile は変更していない**（調査のみ）。前提は [npm-2026-10.md](npm-2026-10.md) と #353 / #354（#357 / #358 マージ後の main）。

## 結論

- **runtime の critical は 0 件。runtime の high は 1 つの根本原因のみ**。`decode-uri-component@0.2.2`（GHSA-qr28-fpjm-wq7f は high、GHSA-vcc3-ghjq-m6fr は moderate）。経路は `expo-router@57.0.30 → query-string@7.1.3 → decode-uri-component@0.2.2`。不正なパーセントエンコードを含む URL の解析で CPU を消費する DoS であり、コード実行や情報漏えいではない。
- `npm audit --omit=dev` は 7 件（high 3 = decode-uri-component / query-string / expo-router、moderate 4 = expo / @expo/fingerprint / glob / minimatch）。moderate 4 件は Expo CLI のビルド時ツール（バンドルされない）経由のため dev・build 扱い。**runtime 扱いは decode-uri-component・query-string・expo-router の high 3 エントリ（根本原因は 1 つ）**。
- 全体 57 件の内訳: critical 0 / high 22 / moderate 34 / low 1。runtime 以外の 54 件は dev・build のみ（Appium / WebdriverIO / Jest / ESLint / Expo CLI）。
- 割り当て（パッケージエントリ数）: **A（#353 WebdriverIO 10）15 件 / B（#354 Expo SDK 58）5 件 / C（同一メジャーで即対応）3 件 / D（受容して記録）34 件**（合計 57）。
- 推奨順序: (1) C を `npm update` で適用（Appium 3.9.0 系。lockfile のみの小さな変更）→ (2) A（WebdriverIO 10.2.0。E2E 専用の high 12 件を解消）→ (3) B（SDK 58 移行。runtime の high を解消）→ (4) A・B・C 適用後に再監査し、D の残りを記録。runtime の high は DoS のみで影響が限定的なため、移行規模の大きい B より A・C を先行してよい。

## 区分の判断基準

- **runtime**: Metro がバンドルするアプリコード、または Tauri / ネイティブアプリに同梱される依存。実行時に端末で動く。
- **dev・build**: Expo CLI・Metro・Jest・ESLint・Appium・WebdriverIO など、開発機または CI でのみ動くもの。`--omit=dev` に出ても、`expo` 本体が依存する `@expo/fingerprint`（ビルド時のネイティブ指紋計算）は CLI 専用でバンドルされないため dev・build とする。

## 割り当ての内訳

- **A（#353 WebdriverIO 10 / Mocha 更新、15 件）**: @puppeteer/browsers、@wdio/appium-service、@wdio/cli、@wdio/config、@wdio/local-runner、@wdio/mocha-framework、@wdio/runner、@wdio/utils、basic-ftp、extract-zip、get-uri、pac-proxy-agent、proxy-agent、webdriver、webdriverio。E2E 専用の high がまとまって解消する。
- **B（#354 Expo SDK 58 移行、5 件）**: decode-uri-component、query-string、expo-router、expo、@expo/fingerprint。runtime の high はここで解消する。
- **C（同一メジャーで即対応、3 件）**: follow-redirects、body-parser、@appium/base-driver。
  - **対応済み（2026-11-11、#361 の PR）**: appium を 3.9.0 へ更新。follow-redirects・body-parser の high は解消。@appium/base-driver は body-parser 分が解消し、glob 経由の分のみ D として残る。npm audit は 57 件から 55 件（high 22 → 17）。
  - **対応済み（2026-11-12、#354 の PR）**: Expo SDK 57 → 58（expo 58.0.24 / expo-router 58.0.31 / React Native 0.88.1 / React 19.3.0）へ移行。decode-uri-component・query-string・expo-router の runtime high 3 件は解消し、`npm audit --omit=dev` は 7 件 → 3 件（high 0 / moderate 3）。全体は 55 件 → 52 件（high 17 → 14、本 PR 時点の main 基準）。expo・@expo/fingerprint は fingerprint が glob / minimatch を引き続き要求するため moderate のまま残る（dev・build のみ。D 扱いで受容）。
- **D（受容して記録、34 件）**: glob、minimatch、readdir-glob、archiver、test-exclude、deepmerge、Appium 一式の残り 8 件、Jest 一式の残り、typescript-eslint 5 件。いずれも dev・build 専用でアプリには同梱されない。悪用には開発機・CI 上で信頼できない入力（悪意あるグロブパターンや zip 等）を処理させる必要があり、現実的な到達性は低い。A・B・C の適用後に再監査し、残ったものを本ファイルに追記する。

## 再監査結果（2026-11-12、#365）

C（#361）・A（#353）・B（#354）をすべて main に取り込んだ後、`expoApp` で `npm ci` → `npm audit` を再実行した。

- `npm audit`: 当初 72 件（critical 3 / high 30 / moderate 38 / low 1）→ **44 件（critical 0 / high 0 / moderate 43 / low 1）**。
- `npm audit --omit=dev`: **3 件（moderate のみ）**。expo / @expo/fingerprint / minimatch で、いずれも Expo CLI のビルド時専用（区分 D）。アプリに同梱され実行時に到達する high / critical は 0 件。
- 残件はすべて区分 D（受容）。理由は次のいずれか。
  - **上流未修正**: 根本原因は `minimatch`（7.0.0〜11.0.0）と `glob` 系。`@typescript-eslint/*` は audit 上 `fixAvailable: true` と出るが、影響範囲が公開済み最新の 8.72.2 まで含むため、実際の修正版はない。
  - **audit の修正案が降格**: `jest@29.7.0`、`appium@2.0.1`、`expo@52.0.49`、`@wdio/*@9.x`、`webdriverio@9.x`、`appium-uiautomator2-driver@9.0.2`（Appium 4 ベータ前提）。既知の脆弱性を含む旧版への降格や未リリース前提の更新になるため採用しない。
- 再確認の条件: `minimatch` / `glob` の修正版が上流（Jest・Appium・Expo CLI・typescript-eslint）に取り込まれたとき、または次回の定期監査時に `npm audit` を再実行し、同一メジャー内で解消できるものから対応する。
