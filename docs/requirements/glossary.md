# 用語集

| 用語 | 定義 |
| --- | --- |
| レシピ | タイトル・説明・何人分・材料・手順・サムネイル画像・手順画像・公開フラグからなる投稿。作成者を「投稿者」と呼ぶ |
| 投稿者 | そのレシピを作成したユーザー。更新・削除・画像操作ができる唯一のユーザー |
| 公開 / 非公開 | レシピの `is_public`。非公開レシピは投稿者本人以外に一切表示しない（フィード・検索・プロフィール・感想すべて）。ただしお気に入りは「自分の非公開レシピ」を自分でつけられる |
| 何人分 | そのレシピが想定する人数（整数 1〜99、必須） |
| 材料 | 「材料名 + 数量（任意）+ 単位（任意）」の 1 行。レシピは 1 行以上の材料を持つ |
| 材料グループ | 材料をまとめる見出し（例「合わせ調味料A」「生地B」）。レシピは 1 個以上の材料グループを持ち、各グループに名前（任意）＋材料リストがある。グループが 1 つで名前なし = 従来のフラットな材料リスト。`ingredient_groups` テーブル |
| 材料のレシピ参照 | 材料行が自分の別レシピへのリンクになっているもの（例「自家製〇〇だれ」）。詳細で材料名タップ → そのレシピ詳細へ。参照先削除時は名前を残しリンク無効。`ingredients.ref_recipe_id` / `ref_recipe_title` |
| 手順 | 順序付きのテキスト 1 行 ＋ 任意の画像 1 枚。`position`（1 起点の連番）で順序を管理する。グループ化はしない |
| サムネイル画像 | レシピを代表する画像 1 枚。一覧カード・レシピ詳細の先頭に表示。画像カルーセルは無い |
| 手順画像 | 各手順に添付できる画像 1 枚。レシピ詳細で手順本文の下に縦に表示 |
| 感想画像 | 感想（コメント）に添付できる画像 1 枚。S3 互換ストレージに保存 |
| `placement`（単位の配置） | 単位を数値の前に出すか後ろに出すか。`suffix`（既定、`200 g`）/ `prefix`（`大さじ 2`）。`prefix` は `大さじ` `小さじ` のみ |
| カーソルページング | 一覧を「前回の末尾位置（cursor）から次の N 件」で取得する方式。オフセット方式と違い、新規投稿による重複・抜けが起きない。全一覧と感想スレッドで採用（無限スクロール） |
| デスクトップアプリ | Windows / macOS にインストールして使うアプリ。**TypeScript トラック**は React Native Web ビルドを Tauri 2 でパッケージ、**Kotlin トラック**は Compose Multiplatform Desktop（JVM）。[tech-stack.md](tech-stack.md) 参照 |
| フロントエンドトラック | フロントの 2 系統の実装。**TypeScript トラック**（React Native + Expo。カリキュラム指定の必須）と **Kotlin トラック**（KMP + Compose。開発者の学習用・随時）。どちらも同じ FastAPI を同じ API 契約で叩く。[tech-stack.md](tech-stack.md) 参照 |
| React Native | JS / TS で iOS・Android のネイティブアプリを作るフレームワーク。UI はネイティブ部品を描画する |
| Expo | React Native の標準ツールチェーン。ビルド・OTA 更新・カメラ / セキュアストレージ等のモジュールを提供。TypeScript トラックのベース |
| Expo Router | Expo のファイルベースのルーティング。`app/` ディレクトリの構造がそのまま画面遷移になる（Next.js App Router 風） |
| React Native Web | React Native のコンポーネントを Web（DOM）向けに描画する仕組み。TypeScript トラックではデスクトップ（Tauri）の土台に使う |
| Tauri | Web フロントを OS のシステム WebView + Rust コアで包み、軽量なデスクトップアプリ（`.msi` / `.dmg`）にするフレームワーク。TypeScript トラックの Desktop シェル |
| NativeWind | Tailwind CSS の記法を React Native で使えるようにするスタイリングライブラリ。TypeScript トラックの UI |
| openapi-typescript | OpenAPI 仕様から TypeScript の型定義を生成するツール。`openapi-fetch`（型安全な fetch クライアント）と組み合わせて使う。[tech-stack.md](tech-stack.md) 参照 |
| 単位マスター（`units`） | アプリ全体で共有する材料単位の候補リスト。入力補完に使う。未登録の単位は保存時に自動追加される |
| 正規化 / `normalized` / `*_normalized` | 検索・重複判定のために、前後空白除去・小文字化・全角/半角そろえをした文字列 |
| ホームフィード | ログイン後のホーム画面。最上部に常時固定の検索窓 ＋「全体 / フォロー / フォロワー / お気に入りレシピ」の 4 サブタブ。すべて無限スクロール |
| フォロー（片方向） | あるユーザーが別のユーザーを一方的に追う関係。承認は不要。相互フォローは自動では起きないが、双方がフォローし合えば成立する |
| フォロー中 | 自分がフォローしているユーザー |
| フォロワー | 自分をフォローしているユーザー |
| お気に入り | ユーザーがレシピに付ける「後で見る」マーク（♡）。レシピ詳細のボタンで登録 / 解除。一覧はホームの「お気に入りレシピ」タブ |
| 感想（コメント） | レシピに対して投稿者本人以外が書く自由記述のテキスト。1 レシピに複数 |
| 通知 | 自分に関係する出来事（フォローされた / お気に入りされた / 感想がついた / フォロー中の新着レシピ）をアプリ内で知らせるもの。ボトムナビ / レールの「通知」アイコンに未読数バッジ |
| 未読 | 通知の `read_at` が NULL の状態 |
| アバター | ユーザーのプロフィール画像 |
| 公開トグル | プロフィールのメール / X / Instagram / その他 URL を「プロフィールに表示するかどうか」の項目別スイッチ。既定は非公開 |
| 秘密の質問 | サインアップ時に登録する「質問文（自由入力）＋ 答え」。パスワードリセットの本人確認に使う。答えはハッシュ保存 |
| アクセストークン | API 認証に使う短命のトークン（例: 15 分） |
| リフレッシュトークン | アクセストークンを更新するための長命トークン。ローテーション方式で 1 回使い切り |
| トークンローテーション | リフレッシュトークンを使うたびに新しいものへ差し替え、古いものを無効化する方式。無効化済みトークンの再提示（リユース）を検知したらチェーン全体を失効 |
| ログインを保持 | ログイン画面のチェックボックス。ON でリフレッシュトークンを端末に永続保存し自動再ログイン、OFF で永続化しない |
| カウント列キャッシュ | フォロー数 / フォロワー数 / お気に入り数 / 感想数を集計クエリではなく非正規化カラム（`users.follower_count` 等）で保持し、増減で更新する方式。トランザクション方針は [non-functional.md](non-functional.md) |
| レシピカード | 一覧画面で 1 レシピを表す共通コンポーネント（サムネイル / タイトル / 投稿者 / お気に入り数）。[screens/components.md](screens/components.md) 参照 |
| ユーザー行 | 一覧で 1 ユーザーを表す共通コンポーネント（アバター / 表示名 / フォロー状態ボタン）。[screens/components.md](screens/components.md) 参照 |
| ボトムナビゲーション | モバイルで画面下部に置く主ナビ。4 destination（ホーム / ＋ / 通知 / マイページ）。[screens/navigation.md](screens/navigation.md) 参照 |
| ナビゲーションレール | デスクトップ / 広幅で画面左に置く主ナビ。ボトムナビと同じ 4 destination |
| 検索窓 | [ホーム](screens/home.md)画面の最上部に常時固定した検索入力欄。表示中のサブタブの集合を、タイトル + 材料名（空白区切り AND）で絞り込む。独立した「検索」destination は持たない。[features/search.md](features/search.md) 参照 |
| マイページ | 自分のプロフィール概要 ＋ アカウント関連メニュー（自分のレシピ一覧 / フォロー・フォロワー / プロフィール編集 / ログアウト）の destination。旧「アカウントメニュー」を画面化したもの |
| destination | ボトムナビ / レールで切り替える主要な行き先。4 つ（ホーム / ＋ / 通知 / マイページ） |
| アプリバー | 各画面の上部の薄いバー（タイトル + 戻る + 文脈アクション）。旧「トップアプリバー」（グローバルな検索バー常駐 + アカウントメニュー）は廃止。検索窓は[ホーム](screens/home.md)専用でロゴ直下に固定 |
| FastAPI | バックエンドの Web フレームワーク（Python）。型ヒントから OpenAPI 3.1 を自動生成し、Pydantic v2 でリクエスト / レスポンスを検証する。[tech-stack.md](tech-stack.md) 参照 |
| ASGI | Python の非同期 Web サーバー / アプリ間インターフェース。FastAPI は ASGI アプリで、Uvicorn（ASGI サーバー）で動かす |
| Uvicorn | FastAPI を動かす ASGI サーバー。開発では `--reload` でホットリロード。本番の実行構成は未定（[todo.md](todo.md)） |
| Pydantic | FastAPI が使うデータ検証 / シリアライズライブラリ（v2）。API のリクエスト / レスポンスモデルを型で定義する |
| SQLModel | バックエンドの ORM。SQLAlchemy 2.0 と Pydantic を組み合わせたもので、FastAPI 作者製。DB モデルと API モデルを親和的に書ける。複雑な制約は生 SQLAlchemy に降りる。[tech-stack.md](tech-stack.md) 参照 |
| Alembic | SQLAlchemy 用の DB マイグレーションツール（読み: アレンビック）。スキーマ変更とシードデータ投入を管理する。SQLModel で表現できない制約は手書きマイグレーションで補う。[data-model.md](data-model.md) 参照 |
| OpenAPI コード生成 | FastAPI が出力する OpenAPI 3.1 仕様（`openapi.json`）から、各言語の API クライアント / 型を生成する仕組み。**Kotlin** は OpenAPI Generator、**TypeScript** は openapi-typescript。バックエンド（Python）と 2 つのフロントで型を一致させる手段。[tech-stack.md](tech-stack.md) 参照 |
| `shared` モジュール | **Kotlin トラック専用**の KMP 共有モジュール（`commonMain`）。フロント内部の共通ロジック（単位の表示整形 等）と、OpenAPI から生成した Kotlin API クライアント / DTO を置く。TypeScript トラックは参照せず、`expoApp` 内に同等物を持つ。[architecture.md](architecture.md) 参照 |
| MVP | 初回リリースに含める機能範囲。未確定。[roadmap.md](roadmap.md) 参照 |
