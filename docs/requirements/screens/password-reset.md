# パスワードリセット

## 1. 目的

パスワードを忘れたとき、登録済みの「秘密の質問」への回答で本人確認し、新しいパスワードを設定する。メール送信は使わない（[`../features/auth.md`](../features/auth.md)）。

## 2. ナビゲーション

- 入口: [ログイン](login.md)の「パスワードをお忘れの方」。
- 出口: [ログイン](login.md)（再設定成功、または戻る）。
- 戻る: ログインへ。
- 認証: 不要。

## 3. レイアウト

2 ステップ（同一画面内で段階表示）:

**ステップ 1**

- メールアドレス入力
- 「質問を表示」ボタン

**ステップ 2**（質問取得後に表示）

- 登録済みの**質問文**（読み取り専用表示）
- 答え入力
- 新しいパスワード入力（表示トグル）
- 新しいパスワード（確認）入力（表示トグル・一致チェック）
- 「パスワードを再設定」ボタン（**答え + 新パスワードを 1 回で送信**）

## 4. 状態

| 状態 | 表示 |
| --- | --- |
| ステップ 1 送信中 | ボタンをローディング表示 |
| 質問取得後 | ステップ 2 を展開。※ 未登録メールでも質問文（実在ユーザーのもの or デコイ）が返る場合がある（[`../features/auth.md`](../features/auth.md) の既知の制約） |
| 新パスワード不一致 | 確認欄の下にエラー、送信ブロック |
| error（400） | 「入力内容を確認してください」（未登録メール / 答え不一致 / パスワード規則違反を区別しない） |
| error（429） | 「試行回数が上限に達しました。しばらくしてからお試しください」 |
| 成功 | スナックバー「パスワードを再設定しました」→ ログイン画面へ |

## 5. アクションと結果

- 「質問を表示」→ `POST /auth/password-reset/request`（`email`）→ 質問文を受け取りステップ 2 へ。
- 「パスワードを再設定」→ クライアント側で新パスワード一致チェック → `POST /auth/password-reset/confirm`（`email`, `securityAnswer`, `newPassword`）。
  - 成功（204）→ サーバー側でそのアカウントの全リフレッシュトークン失効 + `token_version` +1。ログイン画面へ。
  - 400 / 429 → 上記エラー。

## 6. 使用 API

- `POST /auth/password-reset/request`
- `POST /auth/password-reset/confirm`
- （[`../features/auth.md`](../features/auth.md)）

## 7. プラットフォーム差分

- デスクトップ: 各ステップ Enter で進む。
