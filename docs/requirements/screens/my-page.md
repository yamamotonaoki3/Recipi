# マイページ

## 1. 目的

自分のプロフィール概要と、アカウント関連メニューへの入口。旧「アカウントメニュー」を画面に昇格したもの。

> **MVP でのスコープ**: Phase 4（MVP）では **表示名 ＋ ログアウト**のみ。フォロー数 / フォロワー数・「フォロー・フォロワー」メニュー・アバター表示は Phase 5、「自分のレシピ一覧」への導線は Phase 2 で使えるので入れる。「プロフィール編集」は Phase 1 の表示名編集のみ。アカウント削除（[プロフィール編集](profile-edit.md)内）は Phase 9（[../roadmap.md](../roadmap.md)「MVP ライン」）。

## 2. ナビゲーション

- 入口: ボトムナビ / レールの「マイページ」。
- 出口: [自分のレシピ一覧](my-recipes.md) / [フォロー・フォロワー](connections.md) / [プロフィール編集](profile-edit.md) / [ログイン](login.md)（ログアウト）。
- 戻る: マイページのスタックを 1 つ戻す。「マイページ」再タップ → ルートへ。
- 認証: 必要。

## 3. レイアウト（上 → 下）

- アプリバー: 「マイページ」
- プロフィール概要:
  - アバター + 表示名
  - フォロー数 / フォロワー数（タップで[フォロー・フォロワー](connections.md)の該当タブ）
- メニュー（リスト）:
  1. 自分のレシピ一覧 → [my-recipes.md](my-recipes.md)
  2. フォロー・フォロワー → [connections.md](connections.md)
  3. プロフィール編集 → [profile-edit.md](profile-edit.md)
  4. アカウント設定 →（Issue #240・#242。§4 参照）
  5. ログアウト
  6. アカウント削除（ログアウトの下、赤色。確認ダイアログ後にログイン画面へ）

> - **お気に入りレシピ**はここではなく[ホーム](home.md)の「お気に入りレシピ」タブ。
> - アカウント削除は復帰可能な論理削除。公開レシピは残り、再開時にプロフィールとともに復帰する。

## 4. アカウント設定画面（Issue #240・#242・#243）

「プロフィール編集」とは別画面。**現在のパスワードで再認証してから認証情報そのものを変える操作**をここにまとめる（[../features/profile.md](../features/profile.md) §1「役割で分ける」）。

- **秘密の質問・答えの変更**: 現在のパスワード（表示トグル付き）＋ 新しい質問 ＋ 新しい答え（伏せ字、確認用の再入力欄と一致しなければ送信をブロック）。`PUT /users/me/security-question`。現在のパスワード違いは 403 `REAUTH_FAILED`（欄の下に表示。401 にしない＝ログアウトさせない）。
- **メールアドレスの変更**: 現在のパスワード ＋ 新しいメールアドレス ＋ 確認用の再入力欄（不一致はクライアント側でブロック）。送信前に確認ダイアログを挟み、「次回のログインから新しいアドレスを使うこと」「他の端末がログアウトされること」「`emailPublic` が ON なら公開プロフィールの表示も変わること」を明示する。`PUT /users/me/email`。現在のパスワード違いは 403、既に使われているアドレスは 409（欄の下に表示）。成功すると全セッションが失効し、この端末は新しいトークン対で継続する（[../features/auth.md](../features/auth.md) §8）。
- **メールアドレスの変更**は、応答が届かない・端末への保存に失敗した場合、「変更されている可能性があるため、もう一度送信せず、新しいメールアドレスでログインし直してください」を案内し、自動では再送しない（Issue #276。理由は成功時に全セッションを失効させる特性上、再送が冪等ではないため）。**秘密の質問の変更はこの特別扱いの対象外**（204・本文なしで、失敗しても全セッションを失効させないため、通常の「通信エラー。もう一度お試しください」でよい）。

## 5. 状態

| 状態 | 表示 |
| --- | --- |
| loading | 概要部分をスケルトン |
| error（概要取得失敗） | 「読み込みに失敗しました」＋「再試行」。メニューは表示 |

## 6. アクションと結果

- 概要取得 → `GET /users/{自分のID}`（本人取得なので全項目 + フォロー数 / フォロワー数）。
- 「ログアウト」→ [確認ダイアログ](components.md)（任意）→ `POST /auth/logout`（リフレッシュトークン失効）→ 端末のトークンを破棄 → [ログイン](login.md)へ。
- 「アカウント削除」→ 確認ダイアログ → `DELETE /users/me` → 端末の認証情報・キャッシュを破棄 → [ログイン](login.md)へ。

## 7. 使用 API

- `GET /users/{id}`（自分）
- `POST /auth/logout`
- `DELETE /users/me`
- `PUT /users/me/security-question` / `PUT /users/me/email`（アカウント設定画面）
- （[`../features/profile.md`](../features/profile.md) / [`../features/auth.md`](../features/auth.md)）
