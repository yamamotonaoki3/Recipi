# レシピ作成 / 編集

## 1. 目的

レシピを新規作成、または自分のレシピを編集する。機能仕様は [`../features/recipe.md`](../features/recipe.md)（入力項目・バリデーション・行編集 UX）、画像は [`../features/image.md`](../features/image.md)、単位は [`../features/unit.md`](../features/unit.md)。

## 2. ナビゲーション

- 入口:
  - 作成: ボトムナビ / レールの「＋」→ フルスクリーンダイアログ（モーダル）で開く。
  - 編集: [レシピ詳細](recipe-detail.md)の「編集」。
- 出口: [レシピ詳細](recipe-detail.md)（保存成功）/ 呼び出し元（破棄）。
- 戻る: 未保存の変更があれば[確認ダイアログ](components.md)「編集内容を破棄しますか？」。
- 認証: 必要。編集は投稿者本人のみ（他人は開けない）。

## 3. レイアウト（上 → 下）

- アプリバー: 「×」（閉じる）+ タイトル「レシピを作成」/「レシピを編集」+ 右に「保存」
- **サムネイル画像**: 1 枚選択（変更 / 削除）
- タイトル（単一行、1〜120）
- 説明（複数行、0〜2000）
- 何人分（数値ステッパー、1〜99）
- **材料セクション**: 材料グループのリスト。
  - 各グループ: グループ名入力欄（任意、プレースホルダ「例: 合わせ調味料A」）＋ そのグループの材料行リスト（各行「材料名 / 数量 / 単位」、`+` で行追加、各行に削除）＋ グループの削除ボタン
  - 「グループを追加」ボタン
  - 材料行の並べ替え = グループ内 ＋ **ドラッグで別グループへ移動**。グループ自体も並べ替え可
  - 単位欄はオートコンプリート（[`../features/unit.md`](../features/unit.md)）、入力に応じて `大さじ 2` などのプレビュー
  - 各材料行の「レシピから選ぶ」アクション → 下記「材料行のレシピ参照」
  - 初期状態 = 名前なしグループ 1 つ + 空の材料行 1 つ
- **手順の行リスト**: 各行「本文 + 画像を追加ボタン」。`+` で行追加、各行に削除、並べ替え。行頭に手順番号を自動表示。手順はグループ化しない
- **「AI で誤字脱字チェック」ボタン**（本文下部・Phase 11。下記「AI 誤字脱字チェック」）
- 公開フラグ（トグル、既定 OFF）

### 材料行のレシピ参照

- 材料行の「レシピから選ぶ」→ **自分のレシピを選ぶピッカー**（`GET /users/me/recipes`、検索は同エンドポイントの `q`。編集中のレシピ自身は選択不可）。他人のレシピは対象外なので混ざらない。
- 選ぶと `name` にそのレシピのタイトル（60 文字に丸め）が入り、`refRecipeId` がセットされる。`name` は編集可、数量・単位も通常どおり入力可。
- 参照済みの行は名前欄にリンク的な表示（アイコン / チップ）。「リンクを解除」で通常の材料行に戻る（`name` は残る）。

### AI 誤字脱字チェック（Phase 11・[`../features/ai-proofread.md`](../features/ai-proofread.md)）

- 「AI で誤字脱字チェック」ボタン → 現在の入力（タイトル・説明・手順本文・材料名）を `POST /ai/proofread` に送信。
- チェック中はボタンをローディング表示。他の入力操作は継続できる。
- 結果:
  - 変更のある項目に「**修正案**」を並べて表示（`original` → `corrected`）＋ 各項目「適用 / 無視」。「すべて適用 / すべて無視」も。
  - 変更なし → 「誤字は見つかりませんでした」。
  - 失敗（429 / 503 / タイムアウト）→ スナックバー「チェックできませんでした」（429 は「しばらくしてからお試しください」）。**入力は保持、保存はいつでもできる。**
- 「適用」→ その入力欄だけ `corrected` に書き換わる（ユーザーはさらに手で直せる）。「無視」→ 元のまま。
- **陳腐化ガード**: チェック実行中も入力は続けられる。「適用」時、その欄の現在値が `original` と一致しなければ適用せず「内容が変わりました。もう一度チェックしてください」と示す。材料 / 手順 / グループの追加・削除・並べ替えをすると、未適用の修正案はすべて破棄する（対応がずれるため）。
- **AI の修正は自動適用しない。保存フローは AI に依存しない。**

## 4. 状態

| 状態 | 表示 |
| --- | --- |
| バリデーションエラー | 各欄の下にメッセージ。サーバー 400 も同じ欄に反映（複数まとめて） |
| 材料が 0 のグループ | 保存時にクライアント側で除外（エラーにはしない） |
| 保存中 | 「保存」をローディング表示、入力を無効化 |
| 画像アップロード中 | 該当のサムネ / 手順行にスピナー |
| error（通信） | スナックバー「保存に失敗しました」。入力は保持 |
| AI チェック中 | 「AI で誤字脱字チェック」をローディング表示。他の入力は継続可 |
| AI チェック失敗 | スナックバー「チェックできませんでした」（429 は「しばらくしてからお試しください」）。入力は保持 |

## 5. アクションと結果

- 画像選択（サムネ / 手順）→ `POST /images` で一時アップロード → 返った `key` を保持。
- 「レシピから選ぶ」→ `GET /users/me/recipes`（ピッカー一覧。検索は同エンドポイントの `q`）→ 選択で `refRecipeId` セット、`name` にタイトルを自動入力。
- 「保存」→ クライアント側バリデーション → 空の手順行・材料 0 のグループを除外 →
  - 作成: `POST /recipes`（`ingredientGroups`, `thumbnailKey`, `steps[].imageKey` を含む）→ 成功でモーダルを閉じ[レシピ詳細](recipe-detail.md)へ。
  - 編集: `PUT /recipes/{id}`（材料グループ・材料・手順は全入れ替え。**残したい画像・`refRecipeId` も含めて全体を送り直す**。[`../features/image.md`](../features/image.md)）→ 詳細へ戻る。
  - `refRecipeId` が本人所有でない / 自己参照 → 400。その材料行の下にエラー表示。
- 並べ替え → `position` を 1 起点の連番に正規化（グループ・グループ内材料・手順）。手順画像は手順に付いて動く。材料のグループ間移動 = 移動先グループの末尾に付き、両グループの `position` を振り直す。
- 公開レシピを新規投稿 → サーバーがフォロワーへ通知（`followee_new_recipe`）。
- 「AI で誤字脱字チェック」→ `POST /ai/proofread`（`items: [{ id, kind, text }]`）→ `suggestions` を項目ごとに提示。適用したものだけ入力欄を書き換える（Phase 11・[`../features/ai-proofread.md`](../features/ai-proofread.md)）。

## 6. 使用 API

- `POST /images`
- `POST /recipes` / `PUT /recipes/{id}`
- `GET /recipes/{id}`（編集時の初期値ロード）
- `GET /users/me/recipes`（`q` 付き。「レシピから選ぶ」ピッカー）
- `POST /ai/proofread`（AI 誤字脱字チェック・Phase 11。[`../features/ai-proofread.md`](../features/ai-proofread.md)）
- （[`../api.md`](../api.md)）

## 7. プラットフォーム差分

- モバイル: フルスクリーンダイアログ。画像はカメラ / ギャラリー。並べ替え・グループ間移動はドラッグ。
- デスクトップ: 大きめのダイアログ（フルスクリーンでなくてよい、実装時に確定）。画像は OS ファイル選択。並べ替えは上下ボタンも用意。グループ間移動はドラッグまたは「移動先グループを選ぶ」メニュー。
