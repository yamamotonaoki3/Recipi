# 単位マスター（材料の単位候補）

## 1. 目的・概要

材料の「単位」（g、大さじ、少々 など）を、レシピ作成・編集画面で**入力候補（オートコンプリート）**として提示する。デフォルトの単位一式をあらかじめ用意し、ユーザーが自由入力した未登録の単位は自動で候補に追加され、以後は全ユーザーの候補に出る。

## 2. 画面・UI

- レシピ作成・編集画面（[recipe.md](recipe.md)）の材料行「単位」欄。
- 欄をタップすると候補リスト（`units` の一覧）を表示。入力中は前方一致で候補を絞り込む。
- 候補から選んでも、候補にない値を自由入力してもよい。

## 3. 振る舞い・ルール

- **材料行の単位は文字列としてそのまま `ingredients.unit` に保存する。** レシピ表示は `units` マスターに依存しない。
- `units` は入力候補専用のマスター。全ユーザー共通（グローバル）。
- 候補にない単位を自由入力してレシピを保存すると、サーバーが `units` に**自動追加**する。
  - 追加判定は正規化キー `normalized`（前後空白除去・全角/半角そろえ・大文字小文字そろえ）で行い、既存なら追加しない。
  - `g` と `ｇ`（全角）、`kg` と `Kg` は同一とみなす。`g` と `グラム` のような**別表記は統合しない**（打ち間違い・表記ゆれレベルのみ排除）。
- 候補リストはレシピ作成・編集画面を開いたとき（またはアプリ起動時）に取得する。作成中に他ユーザーが追加した単位はその場の候補には出ないが、同じ値を自由入力すれば保存でき（`units` には既にあるので重複追加なし）、次に画面を開くと候補に現れる。**リアルタイム同期は行わない。**

## 3.1 表示ルール（前置 / 後置 / 数量なし）

単位ごとに**配置 `placement`** を持つ。表示（レシピ詳細・一覧・作成画面のプレビュー）は次のルールで整形する。整形ロジックは `shared` モジュールの関数に置き、フロント / バックで共用する。

| 条件 | 表示 | 例 |
| --- | --- | --- |
| 数量あり ＋ `placement = suffix`（既定） | `<数量> <単位>` | `2 個` / `200 g` |
| 数量あり ＋ `placement = prefix` | `<単位> <数量>` | `大さじ 2` / `小さじ 1` |
| 数量なし（`quantity` が null） | `<単位>` のみ | `少々` / `適量` |
| 単位なし（`unit` が null） | `<数量>` のみ | `3` |

- **`prefix` になるのは `大さじ` `小さじ` のみ**（シードで設定）。
- ユーザーが自由入力で追加した単位は `placement = suffix` 固定。ユーザーが `prefix` を選ぶ手段は今回設けない（→ [../todo.md](../todo.md)）。

## 4. データモデル

`units` テーブル:

| カラム | 型 | 制約 |
| --- | --- | --- |
| `id` | uuid | PK |
| `value` | string | NOT NULL（表示用。最初に登録された形） |
| `normalized` | string | UNIQUE, NOT NULL（正規化キー） |
| `placement` | string | NOT NULL DEFAULT `suffix`（`suffix` / `prefix`） |
| `created_at` | timestamptz | |

- `ingredients` からの外部キーは張らない。
- 初期データ = 一般的な和食単位一式。Flyway のシードマイグレーションで投入。`placement` は `大さじ` `小さじ` のみ `prefix`、他は `suffix`。
  - 例: `g` / `ml` / `cc` / `個` / `本` / `枚` / `束` / `パック` / `カップ` / `合` / `少々` / `適量` / `適宜` / `ひとつまみ` / `かけ` / `片` / `房` / `缶` / `袋` / `玉`（= `suffix`）、`大さじ` / `小さじ`（= `prefix`）

## 5. API

### GET `/units`（認証任意）

```json
// response 200
{
  "units": [
    { "value": "g", "placement": "suffix" },
    { "value": "個", "placement": "suffix" },
    { "value": "大さじ", "placement": "prefix" },
    { "value": "小さじ", "placement": "prefix" },
    { "value": "少々", "placement": "suffix" }
  ]
}
```

- 単位の登録専用エンドポイントは設けない。レシピ作成 / 更新（[recipe.md](recipe.md) の `POST` / `PUT /recipes`）時にサーバーが各材料（`ingredientGroups[].ingredients[].unit`）の `unit` を見て未登録単位を自動 upsert する（`placement` は `suffix`）。

## 6. バリデーション

| 項目 | ルール |
| --- | --- |
| 材料行の単位 | 任意。0〜20 文字。自動追加の際は正規化キーで重複排除 |

## 7. 受け入れ基準

- [ ] 単位欄をタップすると初期シードの単位が候補表示される
- [ ] 入力中の文字列で候補が前方一致で絞られる
- [ ] 候補にない単位を入力してレシピ保存でき、次回以降その単位が候補に出る
- [ ] 既存単位と正規化キーが一致する入力では `units` に重複行が増えない（`g` と `ｇ` は 1 行）
- [ ] `g` と `グラム` は別の候補として両方残る
- [ ] `大さじ` を選んで数量 2 を入れると `大さじ 2` と表示される
- [ ] `g` を選んで数量 200 を入れると `200 g` と表示される
- [ ] `少々` を選ぶと数量なしで `少々` のみ表示される
- [ ] ユーザーが自由入力で追加した単位は `placement = suffix` になる
