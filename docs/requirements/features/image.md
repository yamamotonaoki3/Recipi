# 画像アップロード（サムネイル / 手順画像 / アバター / 感想画像）

## 1. 目的・概要

画像を S3 互換オブジェクトストレージに保存する。ローカル開発は MinIO、本番は後日選定（→ [../todo.md](../todo.md)）。扱う画像は 4 種類:

- **レシピのサムネイル画像**（1 レシピに 1 枚・任意）
- **手順画像**（各手順に 1 枚・任意）
- **アバター画像**（1 ユーザーに 1 枚・任意）
- **感想画像**（1 感想に 1 枚・任意。[comment.md](comment.md)）

> 画像カルーセル（レシピに複数枚のギャラリー）は廃止。レシピの写真はサムネイル 1 枚＋手順ごとの画像のみ。

## 2. 画面・UI

### サムネイル / 手順画像

- レシピ作成・編集画面（[recipe.md](recipe.md)）:
  - サムネイル: 画面上部で 1 枚選択（変更 / 削除）。
  - 手順画像: 各手順行の「画像を追加」ボタンで 1 枚（差し替え / 削除）。
- レシピ詳細: 先頭にサムネイル 1 枚（無ければプレースホルダ）。手順リストは本文の下にその手順の画像（あれば）を縦に表示。
- 一覧カード: サムネイルを表示（無ければプレースホルダ）。

### アバター画像

- プロフィール編集画面（[profile.md](profile.md)）: 「変更」「削除」。
- 表示: 一覧カードの投稿者、レシピ詳細の投稿者行、プロフィール、感想の投稿者行、ユーザー行、通知の行為者。無ければプレースホルダ。

### 感想画像

- レシピ詳細の感想入力欄（[comment.md](comment.md)）: 画像添付ボタンで 1 枚選択。感想編集で差し替え / 削除。
- 表示: 感想一覧の各行、本文の下。
- アップロードは `POST /images` → 感想の作成 / 更新 body で `imageKey` を指定。

## 3. 振る舞い・ルール

### アップロードのフロー（サムネイル / 手順画像 / 感想画像）

1. クライアントが画像を選ぶ → `POST /images`（multipart, 認証）で**一時アップロード**。サーバーは先に管理行（所有者 = 認証ユーザー、状態 `pending`）を作ってキーを確定し、オブジェクトを保存してから状態を `stored` にして `{ key, url }` を返す（順序と失敗時の扱いは [../processing-model.md](../processing-model.md) §6・§9）。
2. 本体の `POST` / `PUT` / `PATCH` の body でその `key` を指定して**本参照として紐付ける**。サーバーは、指定されたキーを**リクエストした本人が所有し、かつ「未使用」または「更新対象のこのリソース自身に既に紐付いている」**ことを検証する。他人が所有するキー、または別リソースに紐付いているキーは 400 で拒否する:
   - レシピ（[recipe.md](recipe.md)）: `thumbnailKey` / 各 `steps[].imageKey`
   - 感想（[comment.md](comment.md)）: `imageKey`
3. どこからも参照されない一時アップロードは、一定時間後に GC（定期バッチ）で削除する（[../processing-model.md](../processing-model.md) §8 / 猶予時間は → [../todo.md](../todo.md)）。

- サムネイルと感想画像は単一画像のため、更新時の `thumbnailKey` / `imageKey` は、**省略 = 変更なし**、**現在と同じ既存キー = 維持**、**`null` = 削除**、**新しい未使用キー = 差し替え**とする。
- 手順は `PUT /recipes/{id}` で全入れ替えとなり安定 ID を持たない。画像を残したい手順は、クライアントが既存の `steps[].imageKey` を再送する。`imageKey` が省略または `null` の手順は画像なしになる。
- レシピ・手順・感想の削除、画像の差し替え・削除で参照から外れた旧画像は、**削除キューに積んで定期バッチ（ストレージ削除ジョブ）で実削除する**（削除 API の応答をストレージ障害に巻き込まないため。[../processing-model.md](../processing-model.md) §8・§9）。
- サムネ / 手順画像の追加・変更・削除はレシピ投稿者本人のみ。感想画像は感想の投稿者本人のみ。

### アバター

- `PUT /users/me/avatar`（multipart）で直接設定 / 差し替え、`DELETE /users/me/avatar` で削除。本人のみ。
- アバターは `POST /images` 経由ではなく専用エンドポイントで完結してよいが、**失敗時に孤児オブジェクトや壊れた `avatar_key` を作らない順序**にする（[../processing-model.md](../processing-model.md) §6）: ①新キーの管理行を `pending` で作る → ②オブジェクトを保存 → ③1 トランザクションで `users.avatar_key` を新キーに更新し、旧キーを削除キューに登録する。途中で失敗した新キーは未参照のまま残り GC が回収する。`avatar_key` はオブジェクト保存後にだけ書き換わる。
- `DELETE` は 1 トランザクションで `avatar_key` を NULL にし、旧キーを削除キューに登録する。

## 4. データモデル

画像の正規データはオブジェクトキーとし、表示用 URL はレスポンス構築時にキーから生成する。署名付き URL は失効するため DB に永続化しない。公開バケットを採用した場合は安定 URL を返せるが、その場合も URL はキーから生成される派生値として扱う。

### `recipes`（サムネイル）

| カラム | 型 | 制約 |
| --- | --- | --- |
| `thumbnail_key` | string | NULL 可 |

### `steps`（手順画像）

| カラム | 型 | 制約 |
| --- | --- | --- |
| `image_key` | string | NULL 可 |

### `users`（アバター）

| カラム | 型 | 制約 |
| --- | --- | --- |
| `avatar_key` | string | NULL 可 |

### `recipe_comments`（感想画像）

| カラム | 型 | 制約 |
| --- | --- | --- |
| `image_key` | string | NULL 可 |

> `recipe_images` テーブルは廃止。

## 5. API

### POST `/images`（認証必要、multipart）

- 画像 1 枚を一時アップロード。サムネ / 手順画像 / 感想画像 共通。
- response 201: `{ "key": "uploads/ab12…", "url": "https://…" }`
- レシピ保存時に `thumbnailKey` / `steps[].imageKey`、感想保存時に `imageKey` で参照（[recipe.md](recipe.md) / [comment.md](comment.md)）。

### PUT `/users/me/avatar`（認証必要、multipart）／ DELETE `/users/me/avatar`

- `PUT` → 200（`{ "avatarUrl": "https://…" }`）。`DELETE` → 204。

## 6. バリデーション

| 対象 | ルール |
| --- | --- |
| 形式 | JPEG / PNG / WebP |
| サイズ | 1 枚あたり最大 5MB（初期値、実装時に調整可） |
| サムネイル | 1 レシピに 1 枚 |
| 手順画像 | 1 手順に 1 枚（＝レシピの画像枚数の上限は「手順数 + 1」） |
| 感想画像 | 1 感想に 1 枚 |
| アバター | 1 枚。正方形推奨（トリミング UI は → [../todo.md](../todo.md)） |

## 7. 受け入れ基準

- [ ] `POST /images` で一時アップロードでき、`key` / `url` が返る
- [ ] レシピ作成でサムネイルと手順画像を紐付けて保存でき、詳細に反映される
- [ ] サムネイルを設定 / 変更 / 削除できる
- [ ] 手順ごとに画像を添付 / 削除でき、詳細で本文の下に縦に並ぶ（カルーセルは無い）
- [ ] 非対応形式 / サイズ超過は 400 になる
- [ ] 他人の一時アップロードキーをレシピや感想に紐付けようとすると 400 になる
- [ ] 更新対象自身に紐付いている既存キーは再送して維持でき、別リソースに紐付いているキーは 400 になる
- [ ] レシピ投稿者本人以外はサムネ / 手順画像を変更できない
- [ ] レシピ削除時に、そのサムネ・手順画像がストレージから消える（削除ジョブ対象になる）
- [ ] どのレシピからも参照されない一時アップロードは GC で消える
- [ ] アバターを設定 / 差し替え / 削除でき、各所の表示に反映される
- [ ] 感想に画像 1 枚を添付でき、感想一覧に表示される。感想削除でその画像も消える（削除ジョブ対象）
- [ ] 画像が無いレシピ・手順・ユーザー・感想はプレースホルダ（または非表示）になる
